# 🧮 우선순위는 이렇게 정한다

사람이 읽고 고칠 수 있는 운영 규칙이다. 봇은 이 순서 그대로 계산한다 (`bot.py` 의 `plevel()` · `place()`).
Jira · Linear 에서 흔히 쓰는 방식 그대로 — **우선순위 · 상태 · 담당 · 목표일** 네 가지만 본다.

## 0. 용어 (카드 · 캔버스 · 앱 홈 · 팝업 모두 같은 말)
| 무엇 | 쓰는 말 |
| --- | --- |
| 우선순위 | 🔴 P1 긴급 · 🟠 P2 높음 · 🟡 P3 보통 · ⚪ P4 낮음 — 카드 제목 앞 색 |
| 상태 | `대기` 시작 전 · `진행 중` · `보류` 막혔거나 멈춤 · `확인 대기` 담당자가 끝냈고 요청자·PM 확인을 기다림 · `완료` · `취소` |
| 담당 | 담당 이름 · 「담당 없음 (추천 누구)」 · 💡 = AI 추천이라 본인이 👍 로 확정 전 |
| 목표일 | 📅 9/24 (💡 = AI가 예상 시간으로 제안) · ⚠️ 9/24 지남 |

## 1. 누가 무엇을 하나
- **AI는 숫자만 추정한다** — 할 일마다 가치·긴급·목표 적합·노력(각 1~5), 예상 시간, 먼저 끝나야 할 할 일, 중복, 기능(여러 할 일을 묶는 칸)
- **우선순위는 코드가 계산한다** — 같은 숫자면 누가 돌려도 같은 결과
- **사람이 최종 결정한다** — 누구나 카드에서 바로 상태·우선순위·목표일·담당을 고른다 (Jira·Linear 처럼). 사람이 고른 값은 AI가 덮어쓰지 않는다

## 2. 우선순위
**점수 = (가치 + 긴급 + 목표 적합 × 2) ÷ 노력**

| 우선순위 | 누가 · 기준 |
| --- | --- |
| 🔴 P1 긴급 | **사람만 붙인다** (PoC 전 필수 — 권한·안전·상시 실행 등). AI 는 붙이지 않는다 |
| 🟠 P2 높음 | 점수 7 이상 |
| 🟡 P3 보통 | 점수 4 이상 7 미만 |
| ⚪ P4 낮음 | 점수 4 미만 · 로드맵 단계 밖 · 중복 |

- 목표 적합에 2배를 주는 이유: `project.md` 의 성공 기준에 닿는 일을 앞으로 당기려고
- 노력으로 나누는 이유: 같은 가치면 빨리 끝나는 것을 먼저

## 3. 담당 (일이 몰리지 않게)
- 사람마다 맡은 일은 **5개까지 — 진행 3 + 대기 2**. 우선순위 높은 일부터 추천 담당에게 붙는다
- 나머지는 **담당 없음**으로 둔다 (캔버스 「🙋 담당 없는 일」). 누가 하나 끝내면 우선순위 높은 일부터 추천 담당에게 자동으로 간다
- 먼저 끝나야 할 할 일이 남아 있으면 바로 진행하지 않고 대기로 둔다
- 기다리기 싫으면 카드 ⋯ → ✋ 내가 가져갈게요

## 4. 언제 다시 계산하나
| 때 | 무엇을 | AI 호출 |
| --- | --- | --- |
| 새 할 일이 생김 | 담당 추천 + 숫자 추정 + 전체 재배치 | 있음 (새 할 일만) |
| 상태·담당·우선순위가 바뀜 (✅ 👀 ⛔ ✏️ 👍 ✋) | 전체 재배치만 | 없음 |

## 5. 믿지 말아야 할 때
- AI 숫자는 추정이다. 이상하면 PM이 ✏️ 로 우선순위를 직접 정한다
- AI 점수는 「PoC 전에 필수인지」 를 모른다 — 필수는 PM이 P1 로 정한다
- 목표일 💡 은 예상 시간으로 계산한 제안이다. 담당자가 확인해서 고친다
- 이미 끝난 일을 AI는 모른다 — 끝났으면 ✅ 로 닫아야 순서가 맞는다

## 6. 일정 위험 (현황 · `@PA 현황`)
「언제까지 해야 하는데 안 된 것」 만 본다. 추천은 버튼 하나 — 누르는 게 사람의 승인이다.

| 위험 | 기준 | 추천 |
| --- | --- | --- |
| 지남 | 목표일이 지났는데 안 끝남 | 목표일 다시 정하기 [+3일] |
| 곧 마감인데 시작 전 | 목표일까지 2일 이내 · 대기 | 오늘 시작 [알리기] |
| 못 맞출 것 같음 | 마감일마다 그날까지의 필요 시간 > 가능 시간 (`team.md`) | 그중 우선순위가 가장 낮은 일의 목표일 미루기 [미루기] |
| 단계 마감 | 단계 마감까지 남은 일 > 팀 가능 시간 | 우선순위 낮은 일을 다음 단계로 [옮기기] |
