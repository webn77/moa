# 🗺️ 로드맵

기획 → 프로토타입 → 개발·도그푸딩 → PoC → 판단 → 파일럿 → 본사업. 다음 단계로 넘어가는 기준은 **통과 기준**이다.
PoC 는 통제된 환경(우리 팀)에서 되는지·효과가 있는지, 파일럿은 실제 업무 환경(외부 팀)에서 범위를 좁혀 시범 운영 — 국내 표준 순서 PoC → 파일럿 → 본사업.
할 일을 다 끝내도 기준을 못 넘으면 통과가 아니다.
할 일마다 단계가 붙는다 (카드 ✏️ 에서 바꿀 수 있다). 단계가 없는 할 일은 💤 나중. 사람이 직접 고쳐도 된다.
상태는 끝남 · 진행 · 예정 중 하나. 새 할 일은 「진행」 단계에 붙는다.

| 단계 | 끝나는 날 | 상태 | 하는 일 | 통과 기준 |
| --- | --- | --- | --- | --- |
| 기획 | 2026-09-18 | 끝남 | 문제와 목표를 정하고 도구를 고른다 | Slack + GitHub 로 간다 (Linear 폐기 — 느림·유료) |
| 프로토타입 | 2026-09-19 | 끝남 | sync.py · 첫 봇으로 무료 Slack 에서 캔버스·카드·GitHub 가 도는지 본다 | 캔버스 API 갱신 · 카드 · GitHub 이슈·보드 동기화 실측 성공 |
| 개발·도그푸딩 | 2026-09-24 | 진행 | 기능을 만들면서 우리 일을 이 봇으로 관리한다 | 요청 → 카드 → 담당 → 완료가 끊김 없이 돌고, 전부 GitHub 에 남는다 |
| PoC | 2026-10-01 | 예정 | 우리 팀 1~3명이 1주 동안 통제된 환경에서 쓰며 지표를 잰다 | 지표 3개가 목표에 닿는다 (`project.md`) |
| 판단 | 2026-10-02 | 예정 | 계속 · 방향 수정 · 중단, 그리고 파일럿으로 갈지 정한다 | 판단 회의록이 남는다 |
| 파일럿 | 미정 | 예정 | 외부 팀 1곳의 실제 업무에 범위를 좁혀 시범 운영한다 (판단에서 가기로 할 때만) | 그 팀이 계속 쓰겠다고 한다 → 본사업 |
