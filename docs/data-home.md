# 팀 기록을 어디에 둘 것인가 (정의)

지금은 팀 기록이 **맥 한 대**에 묶여 있다. 그 맥이 꺼지면 최신이 그 안에만 있다. 팀이 쓰는 물건이라면 이건 맞지 않는다.

## 1. 정의 (2026-09-20, 사용자 제기)
1. **팀 기록의 정본은 팀 GitHub 레포다.** 이슈 · 회의록 · 결정 · 상태 전부
2. **실행 호스트(맥 · 클라우드)는 부품이다.** `git clone` + 토큰만 있으면 다른 컴퓨터에서 이어서 돈다
3. **코드 레포와 팀 데이터 레포를 나눈다.** 코드는 모든 팀이 같은 것, 데이터는 팀마다 자기 비공개 레포
4. **비밀은 레포에 넣지 않는다.** 토큰은 실행하는 컴퓨터의 `~/.config/*.env` (권한 600) 에만
5. **개인 기록과 팀 기록을 나눈다.** Claude 세션 전사는 개인 작업 기록, 팀이 알아야 할 것은 이슈·HISTORY·설계 문서로 레포에 옮긴다

## 2. 어디에 둘까 — 후보 비교
| 후보 | 좋은 점 | 문제 |
| --- | --- | --- |
| **팀 GitHub 비공개 레포 (고름)** | 이력이 남고 되돌릴 수 있다 · 팀원 접근 관리가 명확 · 어느 컴퓨터에서나 이어받기 · 이슈·코드와 한자리 | 회사 승인 필요 · GitHub 계정이 있어야 함 |
| Slack 메시지 | 이미 거기 있다 | **무료 플랜은 2026-10-10 부터 1년 지난 메시지·파일을 영구 삭제** (실측) · 검색은 되지만 정본으로 쓰기 어렵다 · API 로 전량 백업은 유료 플랜 기능 |
| Slack 캔버스 | 보기 좋다 | 통째 교체 방식이라 이력이 없다 · 동시 편집 충돌 · 긴 기록에 안 맞는다 |
| Slack 리스트 | 표 형태로 관리 | **Pro 이상** (무료 없음) |
| 실행 컴퓨터에만 | 단순 | 그 컴퓨터가 팀의 단일 장애점 |
| 클라우드 DB(Supabase 등) | 항상 켜져 있음 | 또 하나의 서비스·비용·백업 책임. 지금 규모엔 과함 |

**결론**: 정본은 **팀 GitHub 비공개 레포**. Slack 은 보는 면이고, 실행 호스트는 교체 가능한 부품.

## 3. 날짜별 의사결정 기록
이미 이슈마다 **날짜별 기록**(무엇이 · 누가 · 왜 바뀌었나)이 쌓인다. 여기에 하루 묶음을 더한다.

```
daily/2026-09-20.md     그날 한 줄 요약 + 결정 + 끝난 일(계획대로/늦음) + 새로 들어온 일
issues/NNN-….md         이슈별 날짜별 기록 (있음)
meetings/…              회의록 (있음)
HISTORY.md              큰 결정과 버린 안 (사람이 씀)
```
- 봇이 매일 저녁 그날 기록을 모아 `daily/날짜.md` 로 쓰고 커밋한다. 없으면 만들지 않는다
- 결정은 **이유와 함께** 남는다 — 이미 봇이 「🔄 목표일 9/23→9/26 · 이동원 (권한 검토가 길어져서)」 형태로 쌓고 있다
- 아침 현황의 「지난 기록」 이 이 파일을 가리킨다

## 4. 보안
| 무엇 | 어떻게 |
| --- | --- |
| 레포 | **비공개**. 팀원만 초대. 조직 계정이면 2단계 인증 강제 |
| 토큰 | 레포에 넣지 않는다. `~/.config/*.env` 600. 로그·화면에 값 출력 금지 |
| 비밀 유출 검사 | GitHub Secret scanning + push protection 켜기 (비공개 레포도 지원) |
| 되돌리기 | 잘못 올라간 파일은 커밋 이력에서 지워야 한다 (`git filter-repo`) — 사람이 실행 |
| 회사 승인 | ① Slack 앱 설치 ② 회사 대화를 Claude 로 보내기 ③ **회사 기록을 GitHub(외부)에 두기** — 세 번째가 이 문서의 대상 |
| 회사가 외부 저장을 막는 경우 | 사내 Git 서버(GitHub Enterprise · GitLab) 로 주소만 바꾼다. 봇은 `git push` 대상만 달라진다 |
| 개인 정보 | 이슈에 사람 이름·Slack ID 가 들어간다. 팀 내부용으로만 두고 공개 레포에 올리지 않는다 |

## 5. 만드는 순서
1. 팀 데이터 레포 분리 — `setup.py` 가 데이터 폴더를 git 저장소로 만들고 팀 레포를 연결 (없으면 만들라고 안내)
2. 자동 커밋·푸시 — 바뀐 게 생기면 5분 창, 끌 때 남은 것 처리 (#58 과 같은 자리)
3. `daily/날짜.md` 하루 묶음
4. 새 컴퓨터에서 이어받기 시험 — clone + 토큰만으로 봇이 도는지 (인수인계 #25 와 같은 시험)
