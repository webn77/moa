# 팀 대화방 동선 — 사람이 정하고, AI가 돕고, 기록은 프로젝트 방에

사용자(이동원) 동선 (2026-09-20):
1. 새로운 일이 들어온다 → 2. 「제가 이거 할게요」 → 3. AI에게 「이렇게 정리해 줘」 (체크박스 할 일 목록)
→ 4. 혹은 외부 LLM 에서 진행 후 Slack 에 업데이트 → 5. 최종 산출물이 저장되고 완료

원칙: **백로그 등록도, 완료도 사람이 정한다.** 팀 대화방 = 팀이 AI와 대화하며 일하는 곳 · 프로젝트 방 = 간단한 Jira (카드 · 기록 · 이번 주).

## 벤치마킹 — Linear × Slack
| Linear | 우리 |
| --- | --- |
| **Asks** — 팀 대화방의 메시지가 바로 이슈가 되지 않고 Triage(분류함)로 간다. 사람이 받아들이면 백로그 | ① 요청 → 봇이 정리안 → 사람이 [백로그에 올리기] 를 눌러야 번호가 붙는다 |
| **Synced thread** — Slack 스레드와 이슈 댓글이 양방향 동기화 | 일 이야기는 요청 스레드에서 · 봇이 프로젝트 방 카드에 한 줄씩 기록 |
| **Unfurl** — 이슈 링크를 쓰면 제목·상태·담당이 펼쳐지고 그 자리에서 바꿈 | `#40` 이라고 쓰면 작은 카드가 펼쳐지고 [할게요] [체크] [완료 요청] |
| 요청자에게 상태 알림 | 시작 · 완료 · 확인 요청은 요청 스레드로 (있음) |

## 동선 → 화면
| 단계 | 사람이 하는 것 | 봇이 하는 것 | 어디 |
| --- | --- | --- | --- |
| 1 새 일 | 팀 대화방에 `🎫 한 줄` | 스레드에 정리안 (제목 · 왜 · 추천 우선순위 · 추천 담당) + [📥 백로그에 올리기] [🙋 제가 할게요] [✖ 안 할래요]. **아직 번호 없음** | 팀 대화방 스레드 |
| 1-1 등록 | 버튼 하나 (누구나. PM 만 할지는 팀 설정) | 번호를 붙이고 프로젝트 방에 카드. 누가 올렸는지 기록 | 프로젝트 방 |
| 2 할게요 | [🙋 제가 할게요] → 창: **언제까지**(목표일) · 어떻게(한 줄, 선택) | 담당 · 목표일 확정, 🔄 기록 · 채널 한 줄 「○○ 님이 맡았어요 (목표일 9/25)」 | 요청 스레드 + 프로젝트 방 |
| 3 정리 요청 | 스레드에 `@봇 할 일 정리해 줘` (또는 [🤖 할 일 목록]) | 스레드 대화로 체크리스트 안 → [👍 이대로] 면 체크리스트가 된다 | 요청 스레드 |
| 4 외부에서 작업 | 결과를 스레드에 붙여 넣기 · 파일 · 링크 · 「2번 끝났어요」 | 링크·파일은 [📎 산출물로 저장] 제안, 「N번 끝」 은 체크 | 요청 스레드 |
| 5 완료 | [✅ 완료 요청] (또는 체크 다 함) | 🔍 확인 대기 → 요청자·PM 태그 [확인했어요] → 완료. 산출물은 정본 md 「산출물」 · GitHub | 요청 스레드 → 프로젝트 방 |

요청 스레드 하나가 이슈의 작업 공간이다. 프로젝트 방 카드 스레드에는 기록 한 줄만 쌓인다.

## 이번 주가 잘 보이게
| 어디 | 무엇 |
| --- | --- |
| **팀 대화방 캔버스 「📅 이번 주」** (새로) | 진행 중 — 누가 · 무엇 · 언제까지 · 2/4 / 이번 주 목표일 (예정) / 🔍 확인 대기 / 지난주 끝낸 것 (계획대로 · 늦음). 채널 탭에 늘 있다 |
| 프로젝트 방 작업판 맨 위 | 같은 「이번 주」 한 칸 + 아래에 전체 프로젝트 |
| `@PA 현황` · 아침 9시 | 「이번 주」 먼저 |
| 앱 홈 | 내 이번 주 |

「이번 주 예정」 = 목표일이 이번 주 금요일 이하인 대기 · 진행 중. 목표일을 사람이 정하게 하는 이유가 여기 있다 — 2단계에서 「언제까지」 를 묻는다.

## 실험 순서 (하나씩 써 보고 편한지 본다)
| 실험 | 만드는 것 | 확인할 것 |
| --- | --- | --- |
| A | 1 새 일 → 정리안 + [백로그에 올리기] (사람 확인) | 백로그가 덜 쌓이나 · 버튼 하나가 귀찮지 않나 |
| B | 2 [제가 할게요] + 언제까지 | 「누가 언제까지 뭘」 이 보이나 |
| C | 「📅 이번 주」 캔버스 (팀 대화방) | 이번 주 진행·예정이 한눈에 보이나 |
| D | `#번호` 펼치기 | 이슈를 쉽게 불러오나 |
| E | 3 할 일 정리 · 4 산출물 저장 · 5 완료 요청 | 외부 LLM 결과를 넣기 쉬운가 |

## 분류함을 왜 나중으로 미뤘나 (2026-09-20 결정)

**Linear 가 Triage 를 두는 이유는 「모르는 사람이 넣기 때문」이다.**

| Linear 의 이유 | 우리 |
| --- | --- |
| 밖에서 들어오는 창구가 있다 (고객 지원 Zendesk·Intercom · 다른 팀 · 요청 폼) | **없다** — 밖에서 들어온 요청 0건 |
| 백로그는 「하기로 한 일」 목록이어야 한다. 아무나 넣으면 쓰레기통이 된다 | 넣는 사람이 곧 정하는 사람이다 |
| 넣는 쪽과 받는 쪽을 분리해 둘 다 안 기다리게 | 팀이 2명이라 기다릴 일이 없다 |
| Triage 당번이 매일 비운다 | 당번을 둘 사람이 없다 |

**숫자 (2026-09-20):** 열린 41건 중 이동원 22 · 초기 일괄등록 16 · 봇 3. **밖에서 들어온 것 0건.**

지금 넣으면 본인이 🎫 쓰고 본인이 버튼 누르는 단계가 하나 느는 것뿐이다.
그리고 **분류함은 들어오는 것만 막는다** — 이미 쌓인 담당 없음 31건 · 정의 없음 19건을 한 건도 줄이지 않는다.
그래서 **#57 이슈 정리 도우미**를 먼저 한다.
