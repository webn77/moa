# #30 bot.py 나누기 — 설계

## 왜 2,600줄이 됐나 (2026-09-20 실측)
| 원인 | 근거 |
| --- | --- |
| 기능을 붙일 때마다 한 파일에 더했다 | 이틀 동안 커밋 90여 건. 파일을 나눈 적이 없다 (`core.py` · `messages.py` 만 뺐다) |
| 화면(Block Kit)을 코드 안에서 직접 만든다 | 카드·스레드·앱 홈·팝업·캔버스 화면만 약 660줄 |
| 이벤트 처리 함수가 커졌다 | `on_action` 151줄 (버튼 20여 종을 if 로 나열) · `on_event` 79줄 |
| 같은 일을 여러 길로 한다 | 상태 바꾸기 4갈래 (반응 · ⚙️ · 체크 · 옛 ✏️ 창) · 이슈 정의 3갈래 (질문 · `@정리` · ✏️) |
| 안 쓰는 코드가 남아 있다 | `details_md()` (호출 0) · 옛 ✏️ 창 `edit_card` · `card_menu` · `accept_assign` |

책임별 줄 수: 이벤트 라우팅·실행 499 · 앱 홈·팝업 256 · 상태 변경·기록·확인 248 · 요청·구체화 242 · 현황·일정 위험 227 · 캔버스 216 · 회의 211 · 카드·스레드 화면 193 · 문서 읽기 142 · Slack·AI 호출 45.

## 나눈 모양
```
bot.py            실행만 (67줄) — Socket Mode 연결
handlers.py       이벤트 · 버튼 · 명령 · 창 제출을 받아 flows 로 넘긴다 (3단계에서 표로)
common.py         바탕 — 채널 ID · 용어(상태·우선순위) · 로그 · 작은 도우미 (다른 우리 모듈을 모른다)
config.py         팀 설정 (있음)          messages.py   봇이 하는 말 (있음)
core.py           순수 계산 — 배정·우선순위·상태 규칙·변경 비교 (있음, 테스트)
store.py          상태 저장 — STATE · save · 카드 찾기 · 날짜별 기록(add_log · timeline)
docs.py           팀 문서 읽기 — project.md · team.md · roadmap.md (md_table · load_*)
slack.py          Slack 호출 — api · 이름 · 링크 · 글 올리기/고치기 · 한도 지키며 여러 개 고치기
ai.py             AI 호출 — ask_ai · 추천 담당 · 우선순위 숫자 · 구체화 질문 · 회의록 정리 (프롬프트도 여기)
views/
  card.py         카드 · ⚙️ 설정 · 체크리스트 체크박스 · 📄 상세
  home.py         앱 홈 · 팝업(detail_groups)
  canvas.py       캔버스 마크다운
  digest.py       /상태 현황 · 일정 위험 · 추천
flows/
  intake.py       요청이 들어와서 백로그·이슈가 되기까지 (사람 확인 포함)
  status.py       상태·담당·목표일 바꾸기 한 길 — 확인 대기 · 결정 이력 · 알림(announce)
  meeting.py      회의 · 회의 결정 → 이슈
  fix.py          일정 위험 [적용]
  github.py       정본 md · GitHub 내보내기·댓글 가져오기 (gh_link.py 를 여기로)
```
규칙: `views/` 는 화면만 만들고 Slack 을 부르지 않는다 · `flows/` 만 상태를 바꾼다 · `core.py` 는 아무것도 모른다 · 한 파일 400줄을 넘기지 않는다.

## 순서 (한 번에 다 바꾸지 않는다)
1. **골든 테스트 먼저** — 지금 `cards.json` 으로 카드 · ⚙️ · 상세 · 앱 홈 · 캔버스 · 현황 화면을 뽑아 파일로 저장. 나눈 뒤 같은 입력에서 한 글자도 안 달라야 통과
2. **옮기기만** (동작 변경 0) — store · docs · slack · ai → views → flows 순. 단계마다 골든 테스트 · 단위 테스트 · 봇 재시작 확인
3. **라우팅 표** — `on_action` 의 if 나열을 `{action_id: 함수}` 표로
4. **안 쓰는 길 걷어내기** — `details_md` · 옛 ✏️ 창 · `card_menu` · `accept_assign`. 상태 바꾸기는 반응 · ⚙️ 두 길로 (체크박스는 체크리스트만)
5. **동기화 결함 B~E** (원래 #30) — 나눈 구조 위에서
6. **재시작 안전** — 끌 때 하던 일(내보내기·저장)을 마치고 꺼진다. 9/20 #49 GitHub 연결이 재시작 중 끊긴 사고의 재발 방지

## 진행 (2026-09-20)
- 1단계 골든 테스트 ✅ (`tests/golden/`, 화면 220개)
- 2단계 옮기기 ✅ — 16개 파일, 가장 큰 것 366줄 (`handlers.py` · `flows/status.py`). 골든 동일 · 모르는 이름 0 · 실제 봇 재시작 확인
- 동작 골든 추가 ✅ — 버튼·반응·명령·창 제출 31가지의 Slack 호출과 최종 상태 (`tests/golden/actions.py`)
- 3단계 라우팅 표 ✅ — `on_action` 151줄 if 나열 → `ACTIONS` 표 + 버튼별 함수. 버튼 처리 내용은 flows 로 (`take_card` · `check_criteria` · `close_done` · `confirm_spec`)
- 4단계 걷어내기 ✅ — 안 쓰는 코드 4개 삭제 (`details_md` · `by_bucket` · `dates_line` · `PRIO`). **남긴 것**: 앱 홈 「✏️ 상태·담당」 창 — 홈에서 스레드를 찾지 않고 바꾸는 길이라 쓸모가 있다(⚙️ 와 같은 칸). 예전 카드 메시지의 `accept_assign` · `⋯` 메뉴 버튼은 Slack 에 남아 있을 수 있어 연결만 둔다
- 5단계 동기화 결함 ✅ — B 보드 정보 한 번만 조회 · D GitHub 번호를 숫자(`gh_no`)로 따로 · E push 실패를 로그에 ⚠️. C(일괄 내보내기 push)는 일괄 내보내기 코드가 없어 해당 없음
- 6단계 재시작 안전 ✅ — 저장은 임시 파일 → 바꿔 끼우기 · SIGTERM/Ctrl+C 면 새 이벤트를 그만 받고 하던 일을 마친 뒤(최대 30초) 저장하고 꺼진다. 실제 봇으로 「끄는 중 → 꺼짐」 확인 · 테스트 `tests/test_restart.py`
- 남은 것 (#30 밖): `issues/*.md` 본문은 사람 소유·봇은 머리말만 (검토 a) · 메시지 삭제 시 「취소/유지」 묻기 (검토 b) — 별도 이슈로

## 체크리스트
- `bot.py` 200줄 이하 · 한 파일이 **600줄을 넘으면 그때 다시 나눈다**
  (2026-09-20 사장님 결정. 원래 「모든 파일 400줄 이하」 였는데, 나눈 뒤 기능을 얹으면서
  `handlers.py` 500 · `core.py` 456 이 됐다. **숫자는 수단이지 목적이 아니다** — 잘 돌고 있는
  코드를 400 때문에 다시 나누면 얻는 것보다 위험이 크다. 한 번 나눴고, 더 늘면 그때 건드린다)
- 골든 테스트 · 단위 테스트 전부 통과 (나누기 전후 화면 동일)
- 안 쓰는 코드 4곳 삭제, 상태 바꾸는 길 2개
- 봇을 끄는 중에 누른 동작이 끊기지 않는다 (시험으로 확인)

이 문서는 **#30(bot.py 나누기) 한 이슈의 설계**다. 그 뒤로 구조에 얹힌 것들:

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| **여러 프로젝트** | `store.chan()`·`req()`·`canvas_of()`·`project_of()` | 방·작업판이 상수였다 — 88곳에 박혀 있어 프로젝트를 바꾸려면 봇을 다시 띄워야 했다 (#70) |
| **통로** (`ask.jsonl`) | `flows/control.py` | 도구(Claude·스크립트)가 봇에 일을 맡기는 **한 길**. 처리한 줄은 `ask.done.jsonl` 로 (#56) |
| **봇은 늘 하나** | `bot.claim()` — 파일 잠금 | LaunchAgent 로는 안 막힌다. 손으로 띄운 둘째를 막는다 (#10) |
| **켤 때 git pull** | `gh_link.pull()` | 받는 곳·버전·누가 올렸는지를 PM 에게 DM (#59) |
| **「…하는 중」** | `slack.thinking()` | Slack 의 AI 앱 자리(`agent_view`). **켜면 반드시 끈다** — 스스로 안 꺼진다 |
| **확인 요청은 DM** | `flows/review.py` | 「봐 주세요」 는 한 사람에게 하는 부탁이다. 끝났다는 소식만 팀 방에 |
| **말: 이슈 → 할 일** | `messages.py` 전체 | 「이슈」 는 버그 추적기 시대의 말 (`research/words.md`) |

### 지금 크기 (600줄 기준 — #30 체크리스트)

가장 큰 것이 `gh_link.py` 531 · `handlers.py` 486 · `core.py` 456. **전부 기준 안이다.**
`bot.py` 는 132줄(실행과 끄기만). 시험 267개 · 10파일 + 골든 둘.

### 지켜지고 있는 규칙

- **bottom-import** — 순환을 피하려고 파일 맨 아래에서 가져온다. `ACTIONS` 표는 모듈 로드 시점에
  만들어지므로 **아래에서 오는 이름은 lambda 로 감싼다**
- **화면은 `views/`, 흐름은 `flows/`, 계산은 `core.py`** — `core` 는 Slack 을 모른다(그래서 시험할 수 있다)
- **문구는 `messages.py` 한 곳** — `tests/test_messages.py` 가 말투·용어·조사를 지킨다
- **골든** — 화면과 동작이 한 글자도 안 바뀌는지. 바뀌면 의도한 것인지 diff 로 본다
